# V61.19 – New Pay Run Tab Performance Fix

## Scope
This release changes only the New Pay Run tab initialisation/render flow.

## Changes
- Removes the recursive/redundant `New Pay Run -> openRun() -> setTab('newrun')` rendering loop.
- Shows the New Pay Run tab immediately, then performs the one-time blank-run initialisation on the next animation frame.
- Keeps the current New Pay Run state when switching away and back instead of rebuilding it unnecessarily.
- Removes one duplicate quick-pay-item render during initialisation.

## Unchanged
- Payroll calculations
- PAYE / KiwiSaver / ACC rules
- Duplicate-pay protection
- Timesheets
- Pay items
- Payslips / email / CSV
- Pay run save/finalise behaviour
- Other modules

## SQL
No SQL migration is required.

## Deploy
Deploy the full V61.19 package to Netlify.

## Quick check
1. Open Payroll.
2. Click New Pay Run and confirm the tab appears promptly.
3. Switch to another Payroll tab and back to New Pay Run; entered values should remain.
4. Use Load / Calculate and verify calculations are unchanged.
5. Save/finalise a test run as normal.
