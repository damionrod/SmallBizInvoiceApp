## Official OpenAI documentation checked — 2026-09-18
Only current official OpenAI API documentation was used for the Live transport decision:

- GPT-Live-1 model: `https://developers.openai.com/api/docs/models/gpt-live-1`
- Live create-session API: `https://developers.openai.com/api/reference/typescript/resources/live/methods/create`
- Live API types/events: `https://developers.openai.com/api/reference/typescript/resources/live`

Verified from the current docs:

- model ID: `gpt-live-1`
- Live session endpoint: `POST /v1/live/sessions`
- WebRTC creation request: `session` plus `transport: { type: "webrtc", sdp: <browser offer> }`
- response: `{ session: { id }, transport: { type: "webrtc", sdp: <answer> } }`
- browser applies `transport.sdp` as the peer remote answer
- WebRTC creation starts the Live session; `session.started` is the authoritative startup event
- WebRTC negotiates audio media format; no raw audio format is required in the create request
- Live is full-duplex and GPT-Live-1 is designed for natural interruption handling
- Live server events include session lifecycle, input/output audio state, transcript, usage and close events
- `marin` remains a supported OpenAI built-in voice, so it is preserved

## Old architecture
P6 used:

- model: `gpt-realtime-2.1-mini`
- session type: `realtime`
- endpoint: `POST /v1/realtime/calls`
- multipart SDP/session payload
- Realtime `semantic_vad` configuration

## New architecture
P6.1 uses:

- model: `gpt-live-1`
- session type: `live`
- endpoint: `POST /v1/live/sessions`
- JSON body with `session` + WebRTC `transport`
- browser SDP offer passed to the authenticated Finlo Edge Function
- server uses the permanent `OPENAI_API_KEY` to create the Live session
- server returns only the Live session response/SDP answer and Finlo-safe session metadata
- browser applies `transport.sdp` and continues over the existing WebRTC peer connection

The permanent OpenAI API key remains server-side only.

## Conversation, turn-taking and interruption
GPT-Live-1 now owns the premium Live Voice turn-taking/full-duplex path. The old Realtime `semantic_vad` payload is not sent to the Live endpoint. The P5.1 1,200 ms browser silence timer remains only in the separate browser Voice Conversation fallback and is not used by Live Voice.

A single Live WebRTC session preserves conversational context across turns, including follow-up questions. The existing remote audio track remains the spoken response path. Live-native lifecycle events are accepted by the frontend while older event checks are retained only as harmless compatibility UI-state handling.
