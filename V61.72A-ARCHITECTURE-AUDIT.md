# V61.72A Architecture Audit

## Scope and baseline
V61.72A is a preservation-first architecture consolidation. The runtime baseline used for the frontend is the V61.71B-P6.1 endpoint-fix package. The current production Live Voice session-source correction (removal of the rejected `session.type` field plus the safe provider diagnostic) was mirrored into the package so the source does not regress the already-applied production function. No backend was deployed as part of V61.72A.

## Application map
- `index.html` — customer-facing shell, navigation, modal/form/table markup and module containers.
- `saas.js` — authentication/session orchestration, active business/membership state, entitlements, business switching, settings/subscription/admin orchestration, and ordered operational-module loading.
- `app.js` — invoicing, customers and core invoice/report interactions.
- `expenses.js` — expenses, suppliers, supplier credits/refunds and expense document flows.
- `bank-reconciliation.js` — bank CSV import, mapping, reconciliation and settlement UI.
- `payroll.js` — employees, timesheets, pay runs, payslips and payroll settings UI.
- `job-costing.js` / `job-profitability.js` — job estimates, quotes/costing and actual/profitability presentation.
- `financials.js` — financial statements, GST/BAS presentation and financial reporting UI.
- `accountant-centre.js` — accountant exports and mappings.
- `onboarding.js` — Quick Setup.
- `import-migration.js` — import/migration review/commit UI.
- `finlo-helper.js` — typed Helper, dictation, Basic Voice, Live Voice client path and context.
- `referrals.js` — referral portal/admin UI.
- `supabase/functions/*` — server boundaries for email, OCR, Helper, Live Voice, invites, payments and compliance-source checks.

## Dependency map / safety boundary
`Authentication → active membership/current business → module entitlement → operational module → accounting/GST/reporting`.

Cross-cutting dependencies:
- Business switching updates the authoritative client business context in `SAAS.state.business`; server RLS/RPC validation remains authoritative.
- Operational modules obtain the Supabase client and business context through `window.SAAS`.
- Accounting/GST/reporting depend on accepted lifecycle and posting foundations and are not refactored in this release.
- Helper context is derived from current view/module and business country; Helper remains guidance-only.
- Onboarding writes existing authoritative settings; it does not own a parallel accounting-settings model.
- Import & Migration remains bounded to its accepted commit entities and existing Bank CSV path.

## Findings
### A. Genuine duplication
High-confidence duplication exists in tiny browser primitives (`document.getElementById`, numeric coercion, HTML escaping) and in the operational module loader. V61.72A introduces `finlo-core.js` and adopts it only where semantics are demonstrably identical. The deeply nested dynamic script-loader chain in `saas.js` is replaced by one ordered sequential loader while preserving the exact module order.

### B. Intentional multiple entry points
Settings, operational screens and reports expose some of the same underlying concepts in different contexts. These are retained. Multiple entry points are not treated as duplicate business functionality.

### C. Dead/obsolete code
No material business/workflow code was removed. The evidence threshold for removal was not met for legacy compatibility and dynamically referenced UI code.

### D. Legacy compatibility
The codebase contains versioned CSS overrides and compatibility paths that look old but may affect existing records, mobile layouts or dynamic DOM. They are retained and documented rather than deleted.

### E. Cross-module coupling
The largest high-value coupling found is `saas.js` owning ordered loading/initialisation of operational modules. The order remains authoritative, but loading mechanics are now delegated to a shared primitive. Business and accounting semantics are unchanged.

### F. Shared UI implementations
Buttons, modals, tables, fields, badges and notifications have repeated markup/CSS patterns. Because their current appearances and workflow handlers are already stable but not fully equivalent, V61.72A does not force them into a new generic runtime component. Their structural ownership is documented for future incremental adoption.

### G. CSS duplication / override chains
`styles.css` contains a long chronological cascade of version-specific overrides. Removing or reordering selectors without rendered-browser proof is unsafe. V61.72A therefore performs a behaviour-neutral physical split: the first balanced core/shared portion becomes `styles-core.css`; the remaining historical/module/responsive cascade remains in `styles.css`, loaded immediately after it. Rule order is preserved exactly.

### H. Development/test/diagnostic UI
Live Voice diagnostics are currently support/development-oriented. They are retained because they are actively useful while Live Voice is being validated. Relocation is deferred to V61.72B.

## Authoritative ownership
- Auth/session/business/membership/entitlements: `SAAS` client state + server RLS/RPC enforcement.
- Invoices/customers: `app.js` + Supabase business-scoped data.
- Expenses/suppliers: `expenses.js` + Supabase business-scoped data.
- Bank reconciliation: `bank-reconciliation.js` + existing bank/reconciliation tables/RPCs.
- Payroll: `payroll.js` + existing payroll tables/rules.
- Financial reporting/tax: accepted V61.70 accounting/GST/BAS foundation; frozen.
- Helper Product Knowledge: `v61.71B-P3.1` server source.
- Live Voice configuration/entitlement: existing P6/P6.1 server settings/RPCs; client only consumes status.

## Retained debt
The large HTML shell, historical CSS override chain, module-local formatters/toasts with intentionally different semantics, and some direct DOM coupling remain. They are safer to retain than normalize without full authenticated browser regression coverage.
