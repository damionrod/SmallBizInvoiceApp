# v62.31 Market optional employee payslips

This bounded release adds read-only saved-payslip viewing to the existing isolated employee page. New and relinked employee account access remains leave-only. An owner/admin must explicitly enable payslips for each active employee link, and disabling or replacing the link resets that consent.

The server rechecks the signed-in account, exact link, active employee, business and Payroll availability on every list and detail read. It returns only payslips saved with finalised pay runs. Snapshot identity, pay-run number and dates must match relational records. A malformed legacy snapshot is marked for employer review instead of displaying inferred figures.

The response is an allowlist. It excludes the raw snapshot, IRD number, bank details, email, phone and internal total employment cost. The page labels net as “Take-home pay”; it does not claim that a bank payment occurred. Missing values remain unavailable, and an absent saved currency is never silently treated as NZD.

Migrations:

- `20261018030815_market_employee_payslip_viewing.sql`
- `20261018031046_market_employee_payslip_variable_fix.sql`
- `20261018031308_market_employee_payslip_projection_limits.sql`

The second migration corrects an ambiguous PL/pgSQL record-variable name found during the managed fixture. Applied migration history is retained.

Verification includes frontend controller tests and `ops/market/tests/employee-payslips.sql`, which runs in a rollback boundary and covers default-off consent, stale revisions, finalised-only reads, cross-account denial, raw-row protection, sensitive-field exclusion, link revocation and cleanup. Existing leave, payroll, ledger and provider behavior is unchanged. The feature does not create accounts, send emails, display draft runs or add timesheets.
