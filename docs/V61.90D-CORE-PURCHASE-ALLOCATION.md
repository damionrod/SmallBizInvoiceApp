# V61.90D: purchase allocation in core Financials

The bill, attached pages, source GST, payable and payments remain in Expenses. The optional **Review items** action saves one complete revision of the invoice in `purchase_invoice_reviews`; this works without Stock & Equipment. When that module is enabled, the same server transaction updates its operational register. The module does not own the confirmed accounting allocation.

Financials Summary now shows a purchase allocation schedule derived exclusively from the latest confirmed revision of each active recorded bill in the selected period. It shows Expense, Stock for sale, Materials & supplies, Equipment and Small tools separately, with a count of bills still awaiting review. Prior revisions never add to totals. Summary continues to use the original bill category until a review is confirmed; after confirmation it counts only regular expense items as current estimated expense. The source bill remains the GST and payment source. The report reads the bill's business-use percentage for estimated business purchase costs. If the confirmed review query fails, estimated Summary figures are hidden with an error instead of silently displaying the original bill category.

This is a **purchase allocation schedule**, not a stock valuation, depreciation calculation, posted balance sheet, accounting P&L or income-tax deduction. Posting purchase journals, consumption and sales cost, equipment depreciation, asset disposals and tax schedules require separate controlled accounting work and reconciliation to the source bill, tax rules, chart of accounts, opening balances and closed periods. The posted General Ledger, accounting Profit & Loss and Balance Sheet remain unchanged and continue to include posted entries only. Stock & Equipment remains optional and its quantities/values remain operational estimates.

No SQL migration, Edge Function change, subscription change, production deployment or data backfill is required for V61.90D. The existing V61.90 core purchase review migration is a prerequisite for the review UI and report. No changes were made to the Expenses bill, GST, bank matching, accountant export or stock movement code. Test with a reviewed mixed-use bill and an unreviewed bill in a non-production account after deploying the frontend.

Verification: `node --check public/financials.js`; `node --test tests/*.test.js` (22 tests passed). Added checks cover latest revision, optional-module independence, private-use allocation, voided bills, and failure of the review query. No browser test or staging database integration test was run for this frontend-only change.
