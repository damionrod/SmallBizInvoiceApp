# Frindly Market v62.21 — reliability and guided review

This release belongs only to `market/frindly-market`, Netlify project `2b57d35f-1627-4e0a-82f0-d1817966b606` and Supabase project `smvvevrtjqkflyqkyape`. Main, Dev, production data and production delivery credentials are outside this release.

## Implemented

* Removed the competing delayed Settings-button writer. One revision-checked server command now saves business/settings projections and a field-name-only audit event in one transaction. Browser caches update after a verified server response. An open form retains its original revision, including when another panel saves in the same browser.
* Routed account business details/preferences, late-fee settings and job-costing settings through the same bounded command. Personal profile and authentication details retain their existing authorities.
* Account details are edited in Account. The duplicate company/address/phone inputs in invoice settings now show read-only references with a link to their editor.
* GST/ABN and tax configuration are edited in Tax. Invoice settings show read-only references. The GST rate comes from the existing statutory-rule RPC; it is no longer a free-form override in Financial Settings.
* Financial preferences, effective-dated tax history, current business/financial projections, category mappings, transition-review evidence and accounting-period initialization now save transactionally. A failed mapping rolls back all writes. Future changes are listed and do not become current defaults early. A conflicting identifier requires explicit confirmation in the form. No historical invoice, expense, filing snapshot or journal is rewritten.
* Banking owns account changes. Removed the old name-matching JSON-to-bank writer and its two-request default switch. Bank creation/edit/default/archive now use a tenant-checked command, account revisions and a business-row lock. Creation retries are idempotent. A failed default switch retains the previous default. Archived accounts are not restored implicitly. Default currency must match the business currency.
* New document defaults read the canonical active account projection. Other-currency and archived accounts are excluded. JSON-only legacy instructions remain visible for explicit Banking review; they are not imported automatically. Issued-document snapshots retain their existing readers.
* Business exports now page to completion with stable ID cursors rather than silently stopping at a row limit. They include the newer migration, owner, filing and correction records. Failures are recorded as unavailable datasets, not empty successful exports. Business switches cancel export delivery. Nested credentials are redacted and spreadsheet formula cells neutralised. The manifest explicitly states this is a portability export, not a transaction-consistent backup.
* Income-tax estimates use the configured business year and elapsed days, including January–March, leap years and non-standard balance dates. Missing profit/rates stay unavailable. No fabricated three-way instalment amounts. Usual NZ dates are labelled guidance; no NZ schedule is shown for an Australian business.
* Read-only Tax & IRD overview: saved GST work, filing events, finalised NZ payroll (including no-filing cases), saved tax estimates and instalments. Downloaded/prepared files are not promoted to accepted filings. Saved payments are not presented as a verified myIR balance.
* Starting balances review, reached from Smart Migration Centre: existing CSV parser, explicit column mapping, exact account-code mapping with manual overrides, exact-cent totals, existing-ledger comparison at the day before cutover, missing/duplicate account detection and a downloadable review. This is deliberately a review, not an automatic import/posting command.
* Removed an unused manual-journal global hook; retained the working local action handlers.

## Validation

* Frontend syntax and 61 focused behavioral checks pass.
* All 16 Market isolation/build guards pass.
* 34 database checks pass using temporary, rolled-back fixtures: owner/accountant success, viewer/cross-tenant/anonymous/read-only denial, stale revisions, bank retry/default/archive/currency behavior, projection ownership, NZ/AU tax, future changes, transaction rollback, balanced journals and closed-period guards. No fixture business/profile/account/journal remains committed.
* The complete historical offline suite still has 39 pre-existing failures. Compare the before/after named failures; do not call this suite green. Missing legacy fixtures, old source assumptions and provider-related tests still need individual classification and repair.
* Market build succeeds, retains the production-reference/key guard, CSP, private-site protection and disabled outbound functions. Hosted visual/authenticated acceptance is a separate deployment check; a failed cloud-browser localhost preview is not evidence of UI success.

## Deliberately retained

* Applied migrations, journal/filing/audit history, document snapshots and historical readers.
* Older PERMISSIVE policies that work together with RESTRICTIVE tenant guards. Their age is not proof they are redundant.
* Root-level legacy source copies and old package/deployment files until their local tooling/test consumers move to the canonical `public/` tree. Market publishes only the guarded build from `public/`; the old copies are not competing runtime scripts in this deployment.
* Existing payroll rule/fallback tables and integration adapters until their downstream contracts and historical access are verified.

## Remaining before a commercial-readiness claim

This is not an assertion that every old file or every recommendation is complete.

1. Resolve the 39 historical suite failures with behavioral coverage; complete authenticated desktop/mobile acceptance for the new forms, navigation, export files and permission variants.
2. Complete settings authority for onboarding and payroll-specific employer identifiers; review the known conflicting business/tax identifiers with the business owner. This release does not choose or overwrite them on page load.
3. Extend the existing migration tables/framework for a reconciled trial-balance commit. Reconcile individual unpaid invoices/bills, bank statements, stock/assets, tax and owner accounts. Define serialization with other journal writers, idempotent retry, undo/reversal and period-lock behavior before enabling automatic posting. A balanced CSV alone is insufficient.
4. Complete verified migration fixtures/guides, accountant handoff and dated IR10 mapping. Obtain NZ accounting/payroll review for statutory behavior.
5. Verify restore procedures (including storage files), monitoring/alerts, recovery/MFA design, provider sandbox workflows and a realistic pilot. Test-only outbound services remain intentionally blocked.
6. Consolidate root/deployment/test consumers, then remove proven-unused source/assets in separate small commits. Do not delete old files or policies merely by filename, age or lack of a simple text reference.
7. Specialist tax/practice, native/mobile-store, public API and additional integrations remain demand-led projects from the reviewed roadmap; they were not all authorised as one blind rebuild.
