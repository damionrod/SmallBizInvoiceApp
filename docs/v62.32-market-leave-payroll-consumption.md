# v62.32 Market statutory leave pay-run consumption

This bounded Market release makes confirmed NZ sick, bereavement and family-violence leave a once-only payroll input. The browser includes the existing statutory calculation identifier in its atomic pay-run payload. The server treats that identifier as evidence rather than accepting the displayed line at face value.

On every save the server locks and rechecks the calculation's business, employee, confirmation state, supported leave code, pay-period date, statutory quantity, selected daily rate, total amount and taxable treatment. The calculation is reserved by a saved draft or approval-pending run and remains assigned when finalised. Removing the line while editing releases it. Deleting a draft releases it through the existing foreign-key lifecycle. Reversing a finalised run releases it and records the release beside the existing accounting reversal.

A calculation cannot be included twice in one payload or used by a second pay run. Linked pay lines can only be created inside the trusted atomic save function; the guard also clears its narrow transaction flag immediately after each insert. Existing ordinary, overtime, allowance, reimbursement, PAYE, KiwiSaver, payslip and journal calculations are unchanged.

Verification uses `ops/market/tests/statutory-leave-payrun-consumption.sql` in a rollback boundary. It covers draft reservation, edit release, deletion release, finalisation, reversal release/history, duplicate use in one run, reuse across runs and direct linked-line denial. Frontend regression verifies that both the calculation snapshot and saved pay line carry the statutory identifier.

This release does not alter the statutory formulas, infer employee leave requests into payroll, add a confirmed-record correction editor or complete annual/final-pay review. Main/live is outside this release.
