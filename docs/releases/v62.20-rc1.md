## Verification

Run from the repository root with Node 24.19.0:

```sh
node scripts/check-release.cjs
```

All 35 public JavaScript files pass syntax checks. All 30 focused checks pass. Tests run actual source functions with isolated fixtures; they do not send email, run payroll, charge a card, import records or change production data.

The original full offline suite had 122 tests: 79 passed and 43 failed. After this candidate, the full offline run has 148 tests: 109 passed and 39 failed. The four customer-fixture failures are resolved. No new named failures were introduced. The remaining failures include stale source-text expectations and incomplete VM fixtures, but all require individual review; they are not automatically dismissed as harmless.

To reproduce that full run (it currently exits nonzero):

```sh
node scripts/check-release.cjs --full
```

The authenticated HTTP/RLS test is deliberately excluded from both offline commands because it creates real records when credentials are present. Its staging execution, authenticated multi-role/browser journeys, visual regression, scale tests and backup restoration remain outstanding. The PR workflow runs focused checks; it does not add a production-deployment gate or override Netlify's existing deployment configuration.

Source comparison also verifies unchanged invoice calculation, PDF/preview, customer-editor production code, invoice action-repair code, the expense/payroll/financial modules, CSS, schema migrations and bank operations after account loading. This is useful regression evidence, not a guarantee that no undiscovered defect exists.

## Backend/source reconciliation finding

The complete baseline capture preserved all 620 repository files and source bundles for all 32 deployed Edge Functions. In this candidate, five deployed entrypoints match their repository source, seventeen differ and ten are absent from the repository. See `v62.20-rc1-edge-inventory.json` for versions and source hashes. This comparison concerns entrypoints, not complete schema or deployment reproducibility.

Further differences include request-specific CORS in quote/payslip delivery, live Stripe refund pagination/accounting and BlinkPay changes. In other areas the repository includes protections absent from live code. These are mixed histories, so neither side should overwrite the other automatically. The function-source baseline is retained separately from the active repository; it is not an executable replacement deployment.

Do not bulk-redeploy Supabase functions from this repository or treat the full repository ZIP as a complete production-backend backup. This candidate changes no backend runtime in production. A later source-reconciliation release needs function-by-function review, dependency mapping and isolated integration tests.

## Packaging and rollout

* The full-source ZIP contains every repository file at the candidate revision, including tests, stylesheets, jobs and migration history. It is a repository export, not a database, attachment or live-function backup.
* The small GitHub update ZIP contains only added/changed paths. Extract it and upload those paths over the existing repository while keeping all other files. It fits the 100-file browser-upload limit; it is not a fresh-install/full replacement package.
* No SQL migration or live-data cleanup is needed for this candidate. Do not apply old migrations again.
* Review in an isolated environment before merging to main. Dev integrations must be verified unable to send customer emails or take live payments before executing sending/payment journeys.
* Before live rollout, verify Banking archive/default retention, invoice email status/history, issued-sales totals, customer create/edit/retry and all invoice actions in the browser. Keep remaining full-suite failures explicit in the release decision.

Live website, database records, attachments, memberships, RLS, migrations and deployed backend functions have not been changed by preparing this candidate.

## Rollback
