# v62.22 Market cleanup and workflow reliability

Market only. This release does not complete the full product roadmap or certify commercial readiness.

## Changes

- All previously known offline failures are resolved. Tests now check current paths and behavior rather than historical version strings or an invoice-calculator source hash. The Schedule behavioral harness is managed by the test runner with a timeout; its deferred RPC is reset so the remaining assertions actually execute.
- Payment regression fixtures use current CORS, billing and webhook-lease dependencies; mismatched account, amount, currency, session and intent are rejected.
- Final published JS/CSS bytes generate their own asset hashes. The module loader fetches concurrently with ordered classic-script execution. Community has one script owner and one entitlement/init owner.
- Shared operation guards capture business and user identity. Migration requests cannot continue from an old business form, paint a reopened/closed screen or accept repeated in-flight clicks. Starting-balance review uses the same context guard. Migration formatting uses the business currency; changing a sheet type preserves other column choices, cutover and migration mode.
- The remaining legacy bank undo now uses one invoker-rights, business-scoped server transaction. Payment origin, existing-payment preservation, stale revisions, accounting access, open periods and posted journal dependencies are checked before deletion. Unknown origin or immutable journal dependencies stop for review. Specialized grouped/expense/payroll/owner/refund undo functions retain their existing ownership.
- Two isolated SQL helpers have fixed empty search paths. Anonymous access to the purchase-order send-protection trigger function is revoked. The trigger and public pricing/checkout discovery remain present.
- Removed two unloaded stylesheets from `public/`: their complete trimmed contents already exist verbatim in the active `styles.css`. Root legacy copies remain because the root HTML still uses them. Tests now inspect the stylesheet the Market application actually loads.
- Market CI runs the complete offline suite on every branch push.

## Remaining gates and product work

See `market-cleanup-roadmap.md`. Opening-balance posting remains review-only; no balancing journal is silently created. Leave approvals, employee self-service, optional payrun approval, fuller depreciation/withholding, practice workflows and distribution/integration projects are not represented as completed by this release. Existing statutory calculations and payroll records have not been rewritten.

Authenticated visual acceptance is still blocked by Netlify team protection in the shared browser. Do not remove the protection to obtain a test pass. Commercial acceptance also requires a real database-and-storage restore rehearsal, supported accountant/payroll cases and operational ownership.

## Rollback

Restore the previous Market frontend deploy for a browser regression. The new undo RPC is additive; old clients can coexist. Keep the helper security restrictions. Do not drop applied migration history or revert legitimate user transactions. No source changes are intended for Main.
