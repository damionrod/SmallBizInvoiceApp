# V61.79E Schedule integrity correction

## Scope

This correction is based solely on the consolidated V61.79 Phase B Week-hours package.
It changes only the confirmed findings approved for correction.

Intentionally unchanged:

- the one shared hour range across all seven Week columns;
- `.week-day{min-height:980px!important}`;
- Day-view current-time-marker behaviour;
- DST fall-back ambiguity behaviour;
- recurrence and Google Calendar implementation status;
- payroll role defaults, which were verified as deliberately fail-closed.

## Corrections

1. Schedule and dashboard employee names now use `preferred_name` as a fallback over
   `first_name`, preventing duplicate names.
2. A new additive migration replaces the atomic Schedule RPC with assignment diffing.
   Employees who remain assigned retain `assignment_status`, `planned_hours`,
   `actual_hours`, and audit metadata. Only removed employees are deleted; only new
   employees are inserted.
3. Schedule switches to Day view when crossing below 760 px and restores the previous
   desktop view when crossing back above it.
4. The job editor timezone is now a validated select populated from browser-supported
   IANA zones plus the active business/current value. Save failures provide actionable,
   safely mapped messages while retaining the explicit rollback assurance.
5. Mobile dashboard action and pulse rows have a right-edge fade cue showing that they
   scroll horizontally.
6. Module entitlements are fetched once per active business and shared through a
   15-second cache, preventing repeated per-module queries during the same refresh/focus.
7. Browser cache keys were advanced for the changed CSS, SAAS and Schedule assets.
8. The Schedule employee picker now matches the database availability rule: archived,
   inactive and terminated employees are excluded. The final save payload also removes
   stale or duplicate employee IDs before calling the atomic RPC.
9. Employee allocation is explicitly optional. A job can be saved with no employee and
   assigned later; ordinary clicks toggle multiple employees. V61.79F filters stale IDs
   inside the atomic RPC so they cannot block the job save.
