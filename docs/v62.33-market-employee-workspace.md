# Frindly Market v62.33 — Employee work workspace

This Market-only release groups three compatible employee/payroll roadmap items behind the existing employee account link: read-only leave balances, allowlisted leave history, and employee timesheet drafts/submission.

Timesheet access is optional and off by default. An owner/admin with Payroll and Team write access must enable it for a linked employee. Employee entries use a narrow revision-checked, idempotent database command and feed the existing manager Timesheets list. They do not auto-approve, calculate payroll, post accounting entries, or bypass the existing pay-run rule that only approved timesheets are eligible.

The employee work read API verifies the signed-in account, active link, active employee and active Payroll entitlement. It returns only that employee's allowlisted fields. Leave transaction notes and raw payroll rows are not exposed. Submitted timesheets are locked from employee editing; a manager must reject them before the employee can revise and resubmit. Relinking or revoking employee access resets the timesheet capability to off.

Verification includes JavaScript syntax checks, the full 360-test release suite, and `ops/market/tests/employee-timesheets.sql` in a rollback boundary. The managed fixture covers capability consent, own/cross-account isolation, private-note exclusion, duration calculation, idempotent retry, draft submission locks, raw-row denial, manager approval compatibility, revocation reset and cleanup. Existing pay calculations, leave calculations, payslips and Main remain unchanged.
