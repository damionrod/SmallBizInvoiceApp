# V61.81 Online Invoice Payments

Online Invoice Payments is a separately controlled Frindly module with slug
`invoice_payments`.

## Super Admin rollout controls

1. **Global module** — Super Admin → Modules → Online Invoice Payments → Active.
2. **Subscription plan** — Super Admin → Subscription Plans → include the module.
3. **Individual business** — Super Admin → Businesses → Modules → enable, trial,
   or disable the module for one business.

The individual-business override wins over the plan. Global disablement always
wins over both. Disabling access hides Settings → Payments and Pay Now links,
blocks the public payment page, and preserves all payment/invoice records.

## Payment behavior

- Payments use Stripe Connect direct charges on the subscriber’s connected
  account. Frindly does not hold or re-send invoice funds.
- The invoice amount remains unchanged. A Bear/Split/Pass processing estimate is
  a separate Checkout line item and a separate transaction field.
- Multiple successful payments can be applied to one invoice. The existing
  `customer_payments` ledger and invoice triggers move the invoice through
  Unpaid → Partly Paid → Paid.
- Webhooks, not the browser return page, settle payments. An invoice row lock
  prevents concurrent checkout sessions from over-applying the balance.
- Successful payments send a receipt when the invoice has a customer email.

## Deployment checklist

Apply the migration and deploy the changed functions:

```bash
supabase db push
supabase functions deploy invoice-payments --no-verify-jwt
supabase functions deploy send-invoice
supabase functions deploy stripe-webhook --no-verify-jwt
```

Configure these deployment values:

- `PUBLIC_APP_URL` — deployed Frindly origin used in Stripe return links.
- Existing platform Stripe secret, publishable key and webhook signing secret
  in Super Admin → Payment Settings.
- `RESEND_API_KEY` and the verified `RESEND_FROM_EMAIL` for invoice/receipt
  email.

The Stripe webhook endpoint is the existing
`/functions/v1/stripe-webhook`. It must receive connected-account events as well
as the existing Frindly subscription events. Test in Stripe test mode first,
including a successful payment, partial payment, failed payment, and a second
payment that completes the invoice.

Before enabling the module for a live business, confirm the business has
completed Stripe’s hosted identity and bank-account onboarding and that card
payments are `active`.

## Operational items still needed before broad rollout

- Decide and document who may pass a processing fee to customers and review the
  wording against current New Zealand rules and each payment method’s actual
  Stripe fee.
- Add a business-facing refund workflow and map Stripe refunds/disputes back to
  the invoice ledger before promising automated refund accounting.
- Confirm the operational owner for Stripe disputes, failed payouts, restricted
  connected accounts, and webhook retry alerts.
- Add a production reconciliation review between Stripe balance transactions,
  connected-account payouts, the online-payment transaction table, and the
  invoice/customer-payment ledger.
