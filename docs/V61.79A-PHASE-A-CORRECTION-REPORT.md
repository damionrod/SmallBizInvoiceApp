# V61.79A — Phase A correction report

## Status
Correction-only revision of the V61.79 Phase A database foundation. No frontend file changed. No migration was executed. This package is **not staging-approved**.

## Precise corrections
1. Renamed Google event-link timestamp `frindly_updated_at` → `provider_updated_at`.
2. Optional Schedule/recurrence foreign keys to customers, job costings, quotes, invoices and recurrence series now use `ON DELETE SET NULL`.
3. Assignment and Google event-link `schedule_id` retain `ON DELETE CASCADE` because those child records have no independent meaning after their schedule is deleted. Google sync logs use `ON DELETE SET NULL` for schedule and `ON DELETE CASCADE` for their connection. Assignment employee references use `SET NULL` to preserve assignment history. Employee-owned Google event links use `ON DELETE CASCADE`, because the provider link has no independent meaning after that employee is deleted and this preserves the actor-XOR invariant.
4. Schedule planned times must be both NULL or both present with `end_at > start_at`; every non-unscheduled status requires both. Actual times follow the same paired rule with `actual_end_at > actual_start_at`.
5. Authenticated clients receive SELECT-only access to their own Google connection metadata. INSERT/UPDATE/DELETE is explicitly revoked. Disconnect is deferred to the server-side Google integration phase.
6. Google event links require exactly one actor: employee OR user.
7. Timezones are validated against PostgreSQL `pg_timezone_names`, which is the migration's IANA-compatible source of accepted timezone names. Arbitrary non-empty strings are not accepted.
8. Recurrence convention is 0=Sunday through 6=Saturday. Weekly requires 1–7 unique valid weekdays. Daily/monthly require `days_of_week IS NULL`. All supported recurrence frequencies require a start date, non-null default start time, positive duration and positive interval. End date cannot precede start date.
9. Preflight now validates required columns and PostgreSQL UDT types as well as relations/functions and raises one consolidated fail-closed error before creating V61.79A objects.
10. Rollback is dependency-aware and stops before destructive work if Schedule remains referenced by any staging plan or business override.
11. Added executable SQL staging test harness in addition to static source checks.

## Deletion decisions
- recurrence.customer_id/job_costing_id → SET NULL: recurrence survives source-record deletion.
- schedule.customer_id/job_costing_id/quote_id/invoice_id/recurrence_series_id → SET NULL: schedule remains a historical/operational record.
- assignment.schedule_id → CASCADE: assignment has no independent meaning without schedule.
- assignment.employee_id → SET NULL: intended to avoid blocking employee deletion while preserving assignment history; staging verification required.
- Google event link.schedule_id → CASCADE: provider link has no independent meaning without Frindly schedule.
- Google event link.employee_id → CASCADE: an employee-owned provider link has no independent meaning after employee deletion and cascade preserves the exactly-one-actor constraint. user_id retains the existing auth FK default restriction.
- sync log.connection_id → CASCADE: log belongs to connection.
- sync log.schedule_id → SET NULL: diagnostic history can survive schedule deletion.

## Security
- Schedule remains owner/admin-only until a verified auth-user ↔ payroll-employee mapping exists.
- Schedule entitlement remains plan/per-business based; migration enables no plan or business automatically.
- Google connection metadata is browser read-only; Google-owned state is server-controlled.
- No OAuth token or client-secret columns exist.
- SECURITY DEFINER entitlement/role helpers retain explicit `search_path`, PUBLIC/anon revoke and authenticated execute only.
- RLS remains enabled on every new business-owned table.
- Dashboard unverified financial fields remain NULL with completeness reasons.

- incomplete planned/actual times
