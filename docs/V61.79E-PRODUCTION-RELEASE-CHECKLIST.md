# V61.79E production release checklist

## Release status

This package is a **release candidate**, not an approval to deploy. Do not deploy until
every required gate below is complete. Production project `oxsbzytwbphagcbilxud` has
not been modified while preparing this package.

## Required pre-deployment gates

- [ ] Record a current production database backup/restore point.
- [ ] Confirm the production project and Netlify production site identifiers before any command.
- [ ] Confirm the three prerequisite migration files match the SHA-256 values in this package.
- [ ] Confirm the prerequisite functions and Schedule tables exist in production.
- [ ] Run every JavaScript/static suite from `tests/`; all must pass.
- [ ] Run `tests/v6179a-staging-database-tests.sql` against a disposable/staging project.
- [ ] Run `tests/v6179e-authenticated-http.test.js` with disposable owner credentials and
      `V6179_REQUIRE_AUTH_HTTP=1`; an explicit skip is not a production pass.
- [ ] Capture and inspect a fresh desktop Week screenshot showing the 9:07 PM job.
- [ ] Manually verify an early-morning job and a default-hours-only week.
- [ ] Verify Day view, mobile layout, drag-and-drop and timezone save behavior in the deploy preview.

## Deployment order

1. Freeze unrelated releases for this deployment window.
2. Apply `supabase/migrations/20260920220000_v6179e_schedule_integrity_correction.sql`,
   followed by `supabase/migrations/20260920233000_v6179f_optional_employee_assignments.sql`.
3. Verify both functions are `SECURITY INVOKER`; `anon` cannot execute them and
   `authenticated` can execute them.
4. Repeat the authenticated Schedule save tests against production using a disposable
   production test business: no employee, one employee, and multiple employees. Then
   remove only the test records.
5. Deploy the frontend package.
6. Perform the Week, Day, mobile, drag-and-drop and timezone smoke tests.
7. Monitor browser errors and database logs during the release window.

## Stop conditions

Stop and roll back if any of the following occurs:

- an authenticated Schedule save fails;
- an existing assignment loses progress or audit metadata;
- an out-of-hours job is missing in Week view;
- the active-business/RLS boundary fails;
- any regression suite fails;
- the deployed assets do not match the approved package.

## Rollback

1. Stop the frontend rollout or restore the immediately previous Netlify deploy.
2. For a V61.79F-only rollback, run `docs/V61.79F-ROLLBACK.sql`. To roll back the
   complete V61.79E/V61.79F correction, run `docs/V61.79E-ROLLBACK.sql` instead.
3. Verify the restored function security grants.
4. Re-run the Schedule smoke test and inspect database logs.

The rollback restores the pre-V61.79E function definitions. It does not delete business
data. Because the old atomic-save function replaces all assignments on edit, do not leave
the rollback active longer than necessary if assignment-progress preservation is required.
