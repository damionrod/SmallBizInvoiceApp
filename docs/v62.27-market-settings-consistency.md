# Frindly v62.27 — consistent settings saves

18 October 2026 NZDT. Isolated Market release. Main/live is unchanged.

## Result

Payroll Settings previously saved the main configuration, pay items, leave types and document types in separate requests. A later error could leave only part of the form saved. It now saves those edits and audit in one database transaction, using the revision originally loaded. A stale tab receives a reload message. Values edited while a save is in progress remain visibly unsaved.

Adding and archiving Payroll list items now uses one business-scoped, revision-checked command. A lost response can retry the exact request without creating a second item, including after a data refresh in the same page. A pending uncertain request blocks a different catalog action until resolved. Archived rows remain available to existing historical references.

Bank matching tolerance and confidence preferences now have an audited, revision-checked save. A failed load cannot silently replace saved preferences with defaults. Empty, fractional and out-of-range inputs are rejected. Business changes invalidate late responses. Existing matching calculations and transaction records are unchanged.

## Ownership and cleanup

- `public/payroll.js`: replaces the four split settings writes and direct add/archive calls. Settings and their lists load from one database snapshot.
- `public/bank-reconciliation.js`: replaces the direct preferences upsert and protects preferences loads/saves.

- Existing default-seeding and business-creation functions were traced and retain their privileged writes. No historical table, migration, issued-document snapshot or statutory calculation is deleted or recalculated.

Old root runtime copies remain retained until their packaging consumers are fully traced. Market publishes the canonical `public/` source.

## Deployment and rollback

Only `market/frindly-market` and the Market database are in scope. Run `node scripts/check-release.cjs --full` and `node scripts/build-market.cjs`, compare the complete Git tree with the remote branch, and verify the published commit. Outbound services and Stripe remain disabled.

A browser using the previous cached settings code must refresh. A frontend-only rollback to v62.26 will not restore its revoked direct settings writes. Prefer a forward correction; a full rollback needs a reviewed compensating migration after checking in-flight actions. Never erase applied history or audit evidence.
