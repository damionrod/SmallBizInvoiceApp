# Frindly v62.28 — conversion evidence checks

18 October 2026 NZDT. Market only; Main/live is unchanged.

## User result

Open Migration → Starting balances review, choose the starting date and trial-balance CSV, confirm account mappings, then compare. The review shows source balances, individual-document totals and posted ledger balances for money customers owe and bills to pay. It shows actionable discrepancies and downloads the complete returned evidence with the review.

The CSV must use the business currency. Exact cents are retained. Amount agreement does not approve a conversion. Bank statements, historical tax treatment, stock/equipment/payroll/owner balances and accountant approval remain manual requirements.

## Implementation

`public/starting-balances.js` now calls `v6228_starting_balance_evidence` once instead of independently reading accounts and ledger. The STABLE database function gathers accounts, ledger, dated document/payment/credit/refund summaries and completed financial-import summaries in one snapshot, bounded to the current authorised business. Financials write, report read, core read and expense read access are explicitly checked; anonymous execution is revoked. No source data, journal, account or payment is written by a review.

The check distinguishes payments before cutover from later payments. Advance payments on future-dated invoices/bills are retained without recognising that future document's gross amount at cutover. Estimated legacy payments and later/missing-date voids remain uncertain. Customer/supplier credit and refund totals affect net control balances; credit balances are not silently clamped away. Unposted documents, incomplete import batches, missing/mismatched currencies, malformed amounts, ambiguous controls and fallback tax history remain visible.

Only the first 50 discrepancies display on screen; every discrepancy and all returned evidence remain in the JSON download. More than 20,000 financial/source records causes an explicit full-export error. No partial result is presented as complete. The hash covers the returned summaries, not every possible source-field edit or original source file.

## Limits and rollback

This is the conversion evidence stage. It does not implement the shared opening-settlement authority or post balances. Native part-paid imports and starting-balance posting remain blocked. See `docs/conversion-posting-contract.md` for the proposed remaining treatment and `docs/market-cleanup-roadmap.md` for the full remaining register.

Frontend rollback to the verified v62.27 Market deploy is available; these migrations only add/refine a read API and do not revoke prior readers. Retain applied migration history and use a compensating migration for any backend change. Do not deploy this Market configuration to Main.
