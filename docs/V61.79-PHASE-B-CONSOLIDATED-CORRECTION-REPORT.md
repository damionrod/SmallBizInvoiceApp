## Corrections
- Dashboard now checks every Promise.all result, preserves successful cards, renders unavailable states instead of false zero/empty claims, exposes retry controls, and logs source/code/message/business ID only. Dashboard-summary failure is visible. Cash visual says **Expense payments**.
- Schedule access is resolved by one `SAAS.getScheduleAccess()` result (entitlement + owner/admin). Dashboard, navigation and Schedule consume that result; staff get no Schedule-specific Dashboard UI.
- New additive `20260920175500_v6179_phase_b_atomic_schedule_save.sql` adds `v6179_save_schedule_with_assignments(uuid,jsonb,uuid[])`: SECURITY INVOKER, explicit search_path, active-business + existing role/entitlement check, schedule upsert and assignment replacement in one transaction, PUBLIC/anon revoked, authenticated only.
- Schedule loading separates visible-range scheduled work (2-day buffer) from unscheduled work; checks errors for schedules, assignments and every reference source; incomplete references disable editing; stale business responses are discarded.
- Recurrence creation is disabled and labelled “Recurring scheduling coming next”. No orphan recurrence rules can be created by this UI.
- Schedule time conversion uses selected IANA timezone and defaults from active business timezone (`business.settings.timezone` / `business.timezone`, then NZ fallback). Stored UTC is converted back through the schedule timezone.
- Save buttons have busy/disabled states and duplicate-submit protection. Failed drag restores original position. Failed atomic save preserves original schedule/assignments. Modal supports Escape, focus trap/return, and accessible delete confirmation.
