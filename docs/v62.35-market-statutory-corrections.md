# v62.35 Market statutory leave corrections

This Market-only release adds a controlled correction path for confirmed sick, bereavement and family-violence leave.

## Behaviour

- The original confirmed calculation and taken-leave row remain as audit evidence.
- Corrections require Payroll write access, a reason, the loaded calculation revision and a unique retry identifier.
- The command refuses records already reserved by or linked to a pay run.
- Sick and family-violence entitlement usage is returned atomically.
- An offsetting adjustment row is added; the original calculation becomes `needs_confirmation` with correction metadata.
- The same request can be retried safely. A reused identifier with different input is rejected.
- Family-violence correction reasons remain in restricted operation/audit evidence and are not copied to the general leave-history note.

## Deliberate limits

This is not deletion and it does not rewrite a finalised pay run. A replacement leave record must be recalculated through the existing statutory engine. Annual-holiday and final-pay engines are not exposed as new customer workflows by this release; their complete reviewed save/finalise/correct contract remains a separate payroll acceptance item.

## Verification

The rollback fixture covers successful correction, entitlement reversal, offset evidence, idempotent replay, changed retry rejection, pay-run blocking, direct-write blocking, read-only denial, anonymous denial and full cleanup.
