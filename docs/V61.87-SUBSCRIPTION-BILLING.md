# V61.87 — Subscription & Billing

The account dropdown no longer repeats the subscription link. Businesses manage
Frindly subscriptions in **Settings → Subscription & Billing**. Stripe Connect
and invoice payment settings remain in **Settings → Payments**.

The page shows the business, current plan, price and billing interval, status,
renewal or access end date, invoice usage and available modules. A paid
subscription can be changed in Stripe's hosted confirmation flow, which updates
the existing subscription item instead of creating a second subscription.
Stripe's webhook resolves the chosen plan from its current price rather than
from stale Checkout metadata. The owner retains payment-method and invoice
history actions. The owner and bookkeeper can start cancellation for the
current business in a restricted Stripe flow, or undo a scheduled cancellation
before the period ends. No other roles gain billing permissions.

If Stripe already has more than one active subscription for the same business,
the page identifies the recurring charges and pauses cancellation, payment
method changes and plan changes. The owner can review both in Stripe to stop
the unwanted subscription. This check matters for the existing Care New
Zealand Limited test customer: two active test subscriptions (NZ$39 and
NZ$69 monthly) were already present before this release was deployed. Neither
subscription was canceled, changed or refunded by this release.

Cancellation takes effect at the end of the paid month or year. The Stripe
page displays the end date before confirmation. Stripe's verified webhook and
read-only status refresh keep the business subscription current. After expiry,
operational records remain readable and exportable under the existing role
permissions, but authenticated writes are blocked both in the UI and database.
Stripe invoice-payment settlement by the service role remains possible for
previously issued invoices. A canceled subscription can be renewed through a
new Checkout session; existing records and connected accounts are retained.
Free trials without a Stripe subscription end on their existing expiry date.

Deploy `public/` from the complete archive to GitHub/Netlify; the accompanying
SQL migration and three Supabase functions were applied/deployed to the
connected project in this release. Stripe billing configurations were created
in **test mode** only. The current Care New Zealand Limited subscription was
used only to open a preview of Stripe's cancellation confirmation; the Cancel
button was **not** clicked and no existing subscription was modified.

Validation: local regression tests pass, including isolation tests for
owner/bookkeeper versus other roles, Stripe event order, annual subscriptions,
no duplicate Checkout, trial expiry and past billing access. The database
lifecycle test at `tests/v6187-subscription-access.sql` ran in a rolled-back
transaction and left no fixture business behind. The previous disposable
authenticated HTTP test is skipped without its test-only credentials. A local
browser preview was blocked by the browser environment, so layout should also
be checked on desktop and phone after the Netlify deployment.
