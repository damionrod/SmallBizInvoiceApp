# Frindly Market v62.23 migration safety

Scope: isolated Market only. Main, live database, customer documents, real payroll, real mail and payment providers were not changed.

## Implemented

- Domain-specific permissions before privileged import reads/writes, plus the same checks inside existing old/new SQL entry points and restrictive table policies.
- Access re-evaluated after revocation. Unknown record types fail closed; legacy unknown sheets can be remapped by their uploader or an owner/admin. Raw exports are limited to their uploader and owner/admin oversight, including unclassified extra columns.
- All nine supported record types now pass the sheet-type constraint.
- Exact paid status classification, correct derivation when only outstanding is supplied, preservation of cancelled source history without fabricating a payment, and rejection of contradictory/excessive settlements.
- Only completed imported records count as prior imported duplicates. Analysis alone does not.
- Invoice, expense and quote number collisions stop the whole transaction, preserving original documents and rolling back any earlier customer creation in that attempt. Skip remains an explicit resolution; invoices/expenses also support historical reference.
- Old/new confirmation routes enforce batch ownership; the wrong route cannot falsely mark a batch complete without importing its records.
- Server validation of exact-cent financial totals, settlement totals and business currency. No financial overwrite or foreign-currency conversion is guessed.

## Explicit safety gate

Part-paid operational migration and trial-balance posting are not complete. The legacy expense insert trigger resets outstanding to the full total, while later invoice/expense payment refreshers sum only Frindly payment rows. A correct implementation needs one immutable opening-paid source carried through payment, credit, refund, reporting and posting rules. This release warns about part-paid records and refuses native confirmation until that authority is built. Historical reference is available. It does not invent a bank payment or rewrite already imported data.

## Verification

- 233 full offline tests pass, including 16 new behavioral importer cases across both source variants.
- `ops/market/tests/import-permissions.sql`: actual authenticated RPC and RLS tests; owner, staff, explicit payroll permission, revoked permission, foreign tenant, raw preview, old entry points, permitted customer commit and retry. All fixtures roll back.
- `ops/market/tests/import-financial-conflicts.sql`: successful permitted financial imports, conflicting numbers with full transaction rollback, wrong currency, unbalanced amount, unsafe part-paid rejection, explicit Skip and preservation of original amounts. All fixtures roll back.
- The first two financial migration attempts failed their embedded tests and rolled back completely. Those failures exposed the old sheet constraint and the part-paid balance reset; neither failed attempt is an applied migration.
- No authenticated visual acceptance is claimed while Netlify team protection blocks the shared browser.

## Release and rollback

The four timestamped Market migrations are additive to the audit history. Existing permissive tenant policies remain and restrictive checks narrow them. Do not delete migration history, import evidence or payroll/financial records as rollback. Frontend can return to the previous Market deploy; keep the new security boundary in place. Any backend relaxation or opening-balance implementation needs its own reviewed migration and rollback tests.

The employee portal, leave requests, optional approvals, practice tools, receipt ingestion and separate API/PWA/POS/Peppol/full-tax projects remain tracked in the execution register. This release is not a claim that the whole roadmap is complete or commercially accepted.
