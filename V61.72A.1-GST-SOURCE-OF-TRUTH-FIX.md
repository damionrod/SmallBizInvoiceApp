# V61.72A.1 — GST Source-of-Truth Fix

## Scope
Surgical follow-up to V61.72A. No UI redesign, workflow redesign, accounting rewrite, database migration, Edge Function deployment, or production data mutation.

## Problem found
A deep source scan confirmed multiple frontend fallbacks/defaults that embedded NZ GST at 15%, plus a bank-reconciliation Create Expense path that directly used `rate=15`. These bypassed the configured business GST rate.

## Changes
- `app.js`: removed 15% from default settings and `taxConfig()` fallback. Tax configuration now resolves an explicit/snapshotted rate first, then the active business configured GST rate, otherwise 0.
- `expenses.js`: removed the 15% fallback. NZ expenses now use the active business configured GST rate (with the existing invoice helper setting only as compatibility fallback).
- `job-costing.js`: removed the 15% module default. Existing job-costing configured rate is preserved; otherwise it derives from the business GST setting.
- `financials.js`: removed the 15% UI fallback. NZ GST settings display the business configured GST rate.
- `bank-reconciliation.js`: removed direct `rate=15` when creating an expense from a bank transaction. It now uses the active business configured GST rate and fails safely with a settings message if GST is selected but no rate is configured.
- `index.html`: removed the static `GST (15%)` initial label. Runtime code continues to render the configured rate.
- `saas.js`: cache-bust versions updated only for the modified runtime modules.

## Safety
- No GST/BAS calculation engines, journal posting, lifecycle rules, AR/AP, credits/refunds, payroll, tenant isolation, RLS, or database schema were changed.
- No production backend or Netlify deployment was performed.
- Existing invoice/quote snapshots keep their stored tax values/rates.
- Current NZ statutory GST remains 15%; this release changes where Finlo gets the rate, not the statutory rate itself.

## Static verification
- `node --check` PASS: app.js, expenses.js, job-costing.js, financials.js, bank-reconciliation.js, saas.js.
- Targeted source scan: no remaining operational `gstRate:15`, `??15`, `GST (15%)`, or `rate=15` GST hard-code patterns in application source (excluding documentation/SQL historical artifacts).
- Physical authenticated browser/regression testing remains required after deployment.
