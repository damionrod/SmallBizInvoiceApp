## Human approval gate
- `v6168a_create_draft_ruleset`: Super Admin required.
- `v6168a_set_ruleset_status`: Super Admin required; only Draft → Validated → Approved progression is accepted.
- `v6168a_activate_ruleset`: Super Admin required and rejects any ruleset not already `approved`.
- Detection Edge Function contains no write to `country_payroll_rules` or Payroll transaction tables.
- Draft edits write only `payroll_ruleset_rules` staging records.

## Detection behaviour
Mocked/simulated:
- No-change state: supported by same fingerprint comparison.
- Changed source: creates Review Required event.
- Same change detected again: unique `(source_id, source_fingerprint)` prevents duplicates; transactional fixture returned 1 event.
- Source unavailable/error path: Edge Function records `check_error` and audit detail only; production payroll tables are not touched.
- Changed source with uncertain interpretation: event summary is `Official source changed — manual review required`; no automatic rule extraction/activation.
- Draft creation: clones currently applicable approved production rules into staging only.
- Validation and approval are separate explicit actions.
- Activation is a separate explicit Super Admin action.
