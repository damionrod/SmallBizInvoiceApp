# V61.69C — Frontend Tenant-State Isolation Fix — Test Results

## Release blocker reproduced / root cause

**CONFIRMED.** V61.69B `app.js::allInvoices()` merged the authenticated Supabase result with browser-local invoice data. An empty successful tenant query therefore did not mean “zero invoices”; local records could still be rendered. On Supabase read error/exception it explicitly returned local invoices. This violated cloud-as-source-of-truth tenant isolation.

A related class existed in `allCustomers()` and `getRules()` (recurring invoices): authenticated cloud read failure could fall back to browser operational records. `migrateLegacyLocalData()` could also attempt ownership inference for unscoped legacy operational records unless the old claim marker happened to protect it.

Live DB verification during this correction: Care New Zealand Limited = 27 invoice rows / NZD 67,751.41; Bingo = 0 invoice rows / NZD 0.00; text CC = 0 invoice rows. This confirms the reported Bingo display was not sourced from Bingo invoice rows.

## Exact fix

### app.js
- Authenticated Finlo/SaaS invoice reads are now cloud-only and explicitly constrained to the resolved active `business_id`.
- Successful empty result returns `[]`; no merge with local invoice cache.
- Query error/exception returns `[]`; never previous/local operational data.
- Missing Supabase client or unresolved authorised business returns `[]`.
- If active business changes while a query is in flight, the response is discarded.
- The same fail-closed policy was applied to Customers and recurring invoice rule reads.
- Locally cached pending invoice records are tagged with the active `business_id`; these caches are not used as authenticated read fallbacks.

### saas.js
- Unscoped V22 legacy customer/invoice migration is allowed only when the identity has exactly one active authorised business.
- Multi-business identities never infer which tenant owns old unscoped operational browser records.
- Existing single-business legacy migration compatibility remains available.
- `app.js` cache-buster updated to V61.69C.

### index.html
- `saas.js` cache-buster updated to V61.69C so browsers/CDNs cannot reuse V61.69B tenant-state code.
