# V61.71B-P6 — Finlo Live Voice Implementation Report

## Baseline and scope
Built strictly forward from accepted V61.71B-P5.1. Baseline ZIP SHA-256: `f2df216d5840dfa4efd6a0bbf54fc21b51cdd97f4acad131979ee1f88b9a71bf`; ZIP integrity passed before extraction. P6 preserves Typed Helper, P4 Dictation, P5/P5.1 Browser Conversation, P3 Product Knowledge, P2 route context and all protected accounting/business modules. Netlify was not deployed.

## Current OpenAI research and selected architecture
Official OpenAI documentation was checked on 2026-09-18 before implementation. The current Realtime models support audio/text over WebRTC. P6 uses `gpt-realtime-2.1-mini` by default because it is the current lower-cost Realtime 2.1 model and supports speech-to-speech, WebRTC and tool-capable realtime interaction. The higher-cost selectable option is `gpt-realtime-2.1`. The session uses WebRTC and `semantic_vad` with `create_response:true` and `interrupt_response:true`, so server-side turn detection creates responses and supports interruption/barge-in where the model/API supports it. Default voice is `marin` and is Super Admin configurable.

## Secure WebRTC/session flow
1. Customer deliberately selects **Live Voice** inside the existing Finlo Helper.
2. Frontend checks `v6171b_p6_live_voice_status()` before requesting microphone access.
3. Browser requests microphone via `getUserMedia` and creates an `RTCPeerConnection`, audio track and data channel.
4. Browser creates an SDP offer and sends it to authenticated Supabase Edge Function `finlo-live-voice-session` with business id + P2 Helper context.
5. Edge Function authenticates the Supabase user, resolves authoritative `current_business_id()`, rejects a business mismatch, rechecks global/emergency/entitlement/allowance controls, and only then calls OpenAI `/v1/realtime/calls` with the permanent `OPENAI_API_KEY` on the server.
6. The browser receives only the SDP answer and safe session metadata. The permanent OpenAI key is never returned or embedded in frontend code.
7. Remote audio is attached to an autoplay audio element. Conversation state remains in the OpenAI realtime session until the customer ends it.
8. Ending closes data channel, peer connection, microphone tracks and audio element, and records duration metadata through `finlo-live-voice-end`.

## Product Knowledge and current context
Live Voice is not a generic OpenAI assistant. `finlo-live-voice-session` packages the authoritative P3 Product Knowledge file, version `v61.71B-P3.1`, into the realtime session instructions. It includes actual Finlo navigation, fields, buttons and procedures. The session also receives the current P2 Helper module/view/tab/step/topic and business country. The guidance-only safety rules are carried into the Live Voice instructions.

The invoice knowledge explicitly contains:
- Top menu → **Invoicing** → **Create Invoice**
- **Customer / business name**
- **Invoice date** / **Due date**
- **Invoice items** / **+ Add item**
- **Save Draft**, **Download PDF**, **Send Invoice**

Therefore the required conversation is grounded in actual Finlo knowledge: “How do I create an invoice?” can use the real workflow; “Can I save it without sending it?” remains in the same realtime conversation and the knowledge states **Save Draft**; an interruption such as “Wait, where is that button?” uses the same realtime conversation context, with semantic VAD interruption enabled.

## Conversation/follow-up and interruption
Unlike P5.1, P6 does not transcribe each question into the normal Helper and restart a browser TTS cycle. One Realtime session remains open. OpenAI maintains the live conversation context across turns. `semantic_vad` performs end-of-turn detection. `interrupt_response:true` enables barge-in behavior supported by the current Realtime model/API. The frontend listens to realtime data-channel events to show connecting/listening/speaking state.

## UI and mobile
A **Live Voice** action was added alongside the existing Dictation and Voice conversation modes. The live panel shows realtime state, a compact activity indicator, a reminder that Finlo can be interrupted, and **End Live Voice**. Existing Helper styling is reused. At <=760px the controls use 44px touch targets and remain within the existing Helper bottom sheet; the Helper itself was not redesigned.

## Fallback/error behavior
Live Voice is optional. If it is globally disabled, emergency-disabled, not entitled, out of sessions, unsupported by the browser, microphone permission fails, the secure session broker fails, or the peer connection fails, existing Typed Helper and P5.1 Voice conversation remain available. P6 does not remove or replace those paths.

## Business switching/session termination
Live Voice captures the active business before microphone/session creation. The server independently validates the active business. Normal Helper route changes end an active Live Voice session. The business switch path now explicitly awaits `FinloHelper.endLiveVoice('business-switch')` before switching/reloading, stopping microphone/audio and preventing a live session from carrying across tenants.

## Entitlement, allowance and Super Admin
P6 adds a separate `finlo_live_voice` module and `optional_addon_entitlements` integration. Live Voice does not inherit normal Helper entitlement automatically. Default global state is OFF and existing businesses are not auto-entitled. `v6171b_p6_live_voice_status()` enforces active membership, global/emergency state, entitlement state, monthly session allowance and configured session duration.

Super Admin → Finlo Helper now includes a **Finlo Live Voice** card with global enable, emergency disable, model, voice, max session minutes, default monthly session allowance, KPIs, business entitlement/allowance management, and usage table. Non-Super-Admin access to the admin RPC is rejected.

## Usage/privacy/security
Stored Live Voice usage is metadata only: business id, user id, model, start/end, duration and status. Audio and transcript content are not stored by Finlo P6. Browser microphone audio flows over the realtime WebRTC connection to OpenAI after the authenticated server-side session broker authorises it. Permanent OpenAI credentials remain in Supabase Edge Function secrets. Direct authenticated/anon access to Live Voice settings/usage tables is revoked; customer access is via controlled RPCs/functions.
