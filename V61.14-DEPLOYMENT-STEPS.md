# V61.14 – Duplicate Pay Protection

## Scope
This release changes only duplicate-pay protection in Payroll.

It does **not** change payroll tax calculations, pay rates, payslips, email, reporting, timesheet approval workflow, UI layout, or other modules.

## Deploy
1. In Supabase SQL Editor, run `V61.14-DUPLICATE-PAY-PROTECTION.sql` **once**.
2. Deploy this V61.14 application package to Netlify.
3. Hard refresh the browser after deployment.

## What changes
- New payroll earning lines store the exact `timesheet_id` that generated them.
- Approved timesheets already included in a **finalised** pay run are excluded from later regular pay-run calculations.
- A second database-backed check runs immediately before finalisation.
- Salary employees cannot be finalised twice for the exact same pay period.
- Older finalised hourly runs created before this release are protected conservatively: if the same employee/period is attempted again and the old run has no timesheet links, finalisation is blocked rather than guessing which hours were already paid.
- Deleting the finalised pay run removes its payroll lines through the existing cascade, so its linked timesheets become available to payroll again.

## Quick test
1. Create/finalise a pay run containing an approved hourly timesheet.
2. Create another pay run covering that timesheet's date.
3. Confirm the already-paid timesheet is not loaded again.
4. Try to finalise a stale/duplicate run containing that same timesheet; confirm finalisation is blocked.
5. For a salary employee, confirm a second finalised run for the exact same period is blocked.
6. Confirm a different employee or a genuinely new unpaid timesheet can still be processed.
