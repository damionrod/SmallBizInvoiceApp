# Finlo V61.67 — Job Profitability Upgrade Test Results

## Scope control
- Upgrade was applied additively to the V61.66 baseline.
- Historical Job Costing, Expenses, Payroll and prior migration files were not modified.
- Only the files required for Job profitability, job deep-links, invoice job linkage, scoped UI labels/styles and schema consolidation were changed.

## Database simulation before deployment
- Ran the full V61.67 DDL/backfill inside a PostgreSQL transaction and rolled it back.
- Simulation retained 9 jobs, 13 quotes and 36 invoices.
- Simulation created all expected new columns, 2 tenant RLS policies and 8 V61.67 triggers.
- Confirmed the rollback removed the simulated schema changes before live deployment.
- Ran a cross-tenant manual-cost insertion simulation; it was correctly rejected with `Job belongs to a different business`.

## Live migration verification
- V61.67 migration applied successfully.
- Existing record counts remained: 9 jobs, 13 quotes, 36 invoices, 6 expenses, 11 timesheets.
- Existing jobs were backfilled without inferring completion.
- Existing quoted jobs received immutable original estimate snapshots where available.
- Existing quote→invoice→job links were backfilled only where unambiguous.
- New tables `job_actual_costs` and `job_activity` have tenant RLS enabled.

## Frontend/static tests
- JavaScript syntax checks passed for `app.js`, `saas.js`, `job-costing.js`, `job-profitability.js`, `expenses.js`, and `payroll.js`.
- HTML duplicate-ID check: PASS (0 duplicate IDs).
- 18 targeted workflow assertions passed, including:
  - Quick Quotes remain valid with `job_costing_id = null`.
  - Original frozen estimate is not overwritten by later estimate edits.
  - Split expenses count linked split lines only, not parent + lines.
  - Finalised payroll replaces the matching approved timesheet cost rather than being added to it.
  - Actual revenue uses invoice subtotal ex GST.
  - Contingency stays estimate-only.
  - Expense and Payroll deep-links reuse their existing workflows.
  - Invoice keeps `source_quote_id` while also supporting `job_costing_id`.
  - Job profitability module is entitlement-aware for Expense/Payroll actions.
  - Mobile Jobs cards are enabled below the existing responsive breakpoint.

## Regression boundary
The following historical files were hash-compared with the V61.66 baseline and remained byte-for-byte unchanged:
- `V23-JOB-COSTING-MIGRATION.sql`
- `V24-JOB-COSTING-UPGRADE.sql`
- `V51-MY-EXPENSES.sql`
- `V55-PAYROLL.sql`
- `V61.66-SIGNUP-MEMBERSHIP-MODULE-PROVISIONING.sql`

A full authenticated browser E2E test cannot be performed from the isolated build container because it does not have the user's interactive Finlo login session. Database simulation, live schema verification, syntax/static workflow testing and regression-boundary checks were completed instead.
