# Finlo V61.55 — AI Expense Scanning

## Scope
This release enhances **My Expenses → Add Expense only**. It implements the supplied AI receipt/invoice scanning requirements while preserving the existing manual expense workflow and existing tenant/security model.

## Frontend changes
- Adds a compact **Scan Receipt or Invoice** area to the existing Add Expense capture card.
- Reuses the existing Take Photo / Upload File controls and existing attachment workflow.
- Supports JPG/JPEG, PNG, WEBP and PDF for AI scanning (10 MB max).
- Selected document remains a normal pending expense attachment and is stored only when the user saves the expense.
- AI automatically populates only fields the user has not manually touched.
- AI never saves the expense automatically; the existing **Save Expense** button remains authoritative.
- Adds scan/loading/error/review states, mobile preview and a Scan Again action.
- Uses existing supplier/category data. AI cannot create categories or suppliers.
- If a supplier is not matched, the existing Create Supplier flow is preserved and is prefilled with the detected supplier name.
- Existing tenant-scoped duplicate detection remains in place.
- Existing expense storage, private signed URLs and RLS remain unchanged.

## Backend changes
- New authenticated Supabase Edge Function: `scan-expense-document`.
- Server derives the active tenant through `current_business_id()`; tenant ID is never accepted from the browser.
- Server queries the active tenant's categories and suppliers under the authenticated user's RLS context.
- OpenAI is called only from the Edge Function using `OPENAI_API_KEY`.
- Uses the OpenAI Responses API with image/PDF input and strict JSON-schema Structured Outputs.
- Default model: `gpt-5.6-luna` (overridable with `OPENAI_EXPENSE_MODEL`).
- Additive `expense_ai_scans` telemetry table records tenant/user, status, model and token usage only; document contents/extracted financial data are not stored in this telemetry table.
- Soft abuse protection: 60 scans per user/business per rolling hour.

## Existing code intentionally not changed
No changes were made to invoicing, customers, job costing, payroll, bank reconciliation, financial logic, authentication, subscription logic, Stripe functions, referrals, navigation structure, or existing expense database columns.
